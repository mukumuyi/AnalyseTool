# requirements.md（バグ修正: ⑥-2装置稼働グラフの表示幅不整合）

## 対象バグの説明

`eqp_workload_analysis`レポートの⑥-2「装置稼働グラフ」（設備をクリックで
切り替える段2）で、初期選択設備（パレート図で待機時間合計が最大の設備。
今回の報告例では`EQP252`）以外の設備（例: `EQP009`）を選択すると、
表示されるグラフの横幅が初期選択設備のものと異なる。

### 発生箇所

`output/trial_factory/20260901/eqp_workload_analysis_063431.html`

### 原因（コード調査済み）

- ⑥-2の段1→段2は`common/report.py`の`build_multi_stage_drilldown_html()`が
  「選択式」で実装している。`visualize.py`が上位設備（既定15台）**全員分**の
  `go.Figure`を事前に`fig.to_html()`でレンダリングし、初期選択設備だけを
  `display:block`、それ以外を`display:none`のdivに埋め込んで1枚のHTMLに
  同梱する。
- `fig.to_html()`が埋め込む`<script>`（`Plotly.newPlot(...)`呼び出し）は
  ページ読み込み時に**全設備ぶん同時に**実行される。このとき
  `display:none`のdivは幅を測れないため、Plotlyはその時点で確定した
  （本来より狭い/誤った）サイズのままグラフを描画する。
- 段1（パレート図）の棒をクリックした際の表示切り替え処理
  （`_MULTI_STAGE_TEMPLATE`内、`el.style.display = ... "block" : "none"`の
  部分）は、対象divの`display`を切り替えるだけで、Plotly側へ「サイズが
  変わった」と再計算させる処理（`Plotly.Plots.resize()`等）を一切呼んで
  いない。
- 各図の`config`には`{"responsive": true}`が設定されているが、これは
  主にウィンドウリサイズへの追従用で、`display:none`→`block`という
  プログラム的な表示切り替えには自動追従しないことを確認した
  （実データでも①〜⑤・⑥-1・段2の各設備間で描画データ自体は同じ72本
  ぶんの時間帯であることを確認済みで、データ量の差が原因ではない）。
- 上記より、**初期選択設備のグラフだけ正しい幅で描画され、それ以外の
  設備へ切り替えたときだけ幅がずれる**という、報告と一致する症状になる。

## ユーザーストーリー

分析担当者として、⑥-1パレート図でどの設備を選んでも、⑥-2装置稼働
グラフが毎回同じ正しい横幅で表示されてほしい。現状は初期選択設備以外を
選ぶと幅が崩れ、設備間の比較や読み取りがしづらい。

## 受け入れ条件

1. ⑥-1パレート図で任意の設備（初期選択設備を含む・含まない両方）を
   クリックしたとき、表示される⑥-2装置稼働グラフの描画幅が、初期選択
   設備のグラフと同じになること。
2. 複数の設備を順にクリックして切り替えても、毎回そのつど正しい幅で
   表示されること（一度他の設備に切り替えてから元の設備へ戻す操作も含む）。
3. 今回の修正は`common/report.py`の共通テンプレート（段1→段2の表示切替
   処理）に閉じており、他のレポート要素（①〜⑤、⑥-1本体、⑥-3ガント＋
   仕掛数量推移、⑥-4ロット明細表）の見た目・挙動に影響しないこと。
4. 既存のユニット・結合テスト（`tests/common`・`tests/trial_factory`）が
   通ること。

## 制約事項

- 修正範囲は`common/report.py`の`build_multi_stage_drilldown_html()`
  （段1→段2の「選択式」表示切り替え部分）に閉じる想定。`visualize.py`・
  `analyze.py`側の集計ロジック（時間帯データは既に全設備72本で揃って
  いる）は変更不要。
- 段2→段3（装置稼働グラフ→ガントチャート＋仕掛数量推移）は
  `Plotly.react()`で都度サーバー側ではなくブラウザ側JSが新規に
  Figureを構築する「構築式」であり、表示/非表示の切り替えを伴わない
  ため今回の不具合の対象外（別経路）。
- `docs/`配下の永続文書（`docs/trial_factory/eqp_workload_analysis.md`
  等）への内容変更は不要（既存の仕様通りの表示に戻すバグ修正であり、
  仕様自体の変更ではないため）。

## 画面イメージ（現状 → 修正後）

```
現状:
  ⑥-1パレート図で EQP252 (初期選択) → ⑥-2は正しい幅で表示 ✅
  ⑥-1パレート図で EQP009 をクリック  → ⑥-2が狭い/崩れた幅で表示 ❌

修正後:
  ⑥-1パレート図で EQP252 でも EQP009 でも、他のどの設備でも
  → ⑥-2は常に同じ正しい幅で表示 ✅
```

グラフの種類・軸・配色など見た目の仕様そのものは変更しない
（`docs/trial_factory/eqp_workload_analysis.md`記載の⑥-2の仕様を
そのまま満たす状態に戻すだけ）ため、design.mdでは新たな画面レイアウト
図は起こさず、修正箇所（JS処理フロー）のみを記載する。
